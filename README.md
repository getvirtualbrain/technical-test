## 🧪 Technical Test – Pokémon Application

### 🎯 Objective

Build a web application in **ReactJS** with **TypeScript**, along with a **Node.js/Express** backend.
<!-- note: boilerplate ships both apps, web-app/ and backend/ -->

The backend must call the following Pokémon API to simulate a database:

👉 [https://pokeapi.co/api/v2](https://pokeapi.co/api/v2)
<!-- note: pokeapi has no rate limit but asks clients to cache responses -->

In addition to replicating the required endpoints of this API, you will need to implement two extra routes to transform and download the data.
<!-- note: the two extra routes are the /contents ones below -->

The application must:

- Display all Pokémon in a grid with their image and their stats,
  <!-- note: gen 1 to 8 only, ids 1 to 898 -->
- Include a search bar and filters,
  <!-- note: client side filtering is fine -->
- Allow selecting two Pokémon to simulate a **virtual battle** in an arena,
  <!-- note: two is the minimum, more is a bonus -->
- Display the **battle result** generated by an LLM (large language model).
  <!-- note: raw streamed text is acceptable -->

---

## ⚙️ Required Features

### 🔙 Backend

### 1. General endpoints

- The candidate can either type the required API endpoints, or forward requests directly to `https://pokeapi.co/api/v2/pokemon/*`.
  <!-- note: the boilerplate already adapts pokeapi to its shape -->

### 2. Download endpoints

- `GET /contents/:pokemonId`

    → Fetches a Pokémon's information by its ID, converts the JSON to **Markdown**, and returns the file.
    <!-- note: one file per pokemon, returned as an attachment -->

- `GET /contents/all`

    → Reuses the `/contents/:pokemonId` logic to export the Markdown data of the **898 Pokémon** into a local folder.
    <!-- note: export folder is pokemons-ru (matches the brain import config) -->


### 3. Technologies

- Backend in **Node.js/Express** with **TypeScript**.
  <!-- note: keep strict mode on -->
- Free to use additional libraries (especially for the Markdown conversion).
  <!-- note: hand written conversion is fine too -->

---

### 🧠 Preparing the Arena

### 1. Creating the Brain (LLM)

- Log in to [https://app.getvirtualbrain.com/](https://app.getvirtualbrain.com/) with the password you received by email.
  <!-- note: the account is created by us beforehand -->
- Create a new *brain* and **import the folder generated by `/export`** (the 898 Pokémon).
  <!-- note: /export refers to /contents/all -->
- You can test battles by asking simple questions in the chat, for example:
  <!-- note: indexing the 898 files takes a few minutes -->

    *"What happens if Orbeetle fights Corviknight?"*


### 2. Creating the chatbot

- Create a new **chatbot** from this brain, and get your own **API token**.
  <!-- note: default chatbot settings are enough -->
- Everything you need is in the API documentation: 👉 [https://chatbot-api.getvirtualbrain.com/docs](https://chatbot-api.getvirtualbrain.com/docs)
  <!-- note: keep the token in the backend as a raw string -->

### 3. Using the chatbot

- Query the chatbot through the API to generate the battle. The LLM response is sent as a **stream**.
  <!-- note: reading the docs is part of the test -->

---

### 🖥️ Frontend

### 1. Displaying the Pokémon

- Display all Pokémon in a **responsive grid**.
  <!-- note: mobile included -->
- Each Pokémon card must contain:
    - Its image,
    - Its main stats: **HP**, **Attack**, **Defense**, **Speed**.
      <!-- note: special stats are optional -->

### 2. Search bar and filters

- Add a **search bar** to filter Pokémon by name.
  <!-- note: case insensitive -->
- Add **type filters** (fire, water, etc.).
  <!-- note: 18 types -->

### 3. Selection and battle

- Allow **selecting two Pokémon** to send them into a virtual arena.
- Implement an **LLM prompt** to generate a Pokémon battle; specifying the two Pokémon (or more) along with a few battle instructions should be enough.
- Use the chatbot stream to generate the battle. (The battle obviously doesn't need to be perfect; just getting the stream output is enough.)

#### ⭐ Bonus: turn-based battle

- Instead of letting the LLM simulate the whole battle, use the API's **session management** to play it round by round:
  <!-- note: see the sessions section of the API docs -->
    - Each round, the LLM only **chooses which attack** each Pokémon uses,
    - Your application **computes the result** of the round (damage, HP, KO…),
      <!-- note: the formula is up to you, it doesn't need to match the games -->
    - The result is sent back to the LLM in the same session so it can play the **next round**, until one Pokémon is KO.

### 4. User interface

- The interface is up to you, but it must be **intuitive**. Good design will be appreciated.
  <!-- note: dark mode toggle is already in the boilerplate -->

## ⏱️ Post Scriptum

As you may have noticed, a boilerplate is provided to make your job easier. Feel free to add types, create interfaces, change the existing architecture, and bring your own changes or improvements to it.

If you lean towards front-end, you can spend more time on the UX/UI and completely rework the front end. Conversely, if you are more back-end oriented, feel free to enrich the business logic, structure the code, or improve performance and security.
